# 项目目标、当前状态与分阶段验收

> 更新时间：2026-09-29  
> 状态口径：以当前工作区代码、SQLite 正式库和可重复测试结果为准。

> 本轮进展：已打通透明售房网正常浏览器公开页的“小区检索 → 详情页 → 在售卡片解析 → 审核快照 → 幂等入库”链路。杭州官方监管平台公开旧域名当前 DNS 不可达，系统已增加独立探测适配器和熔断状态。正式库现有 10 条历史成交、10 条当前挂牌观察和 3 份可追溯原始快照。

## 1. 北极星目标

构建面向个人和家庭自住决策的杭州住宅分析工作台，持续回答五个问题：

1. 扣除税费、装修和应急金后，家庭真正买得起什么；
2. 哪些区域和小区更符合多人通勤、教育与生活约束；
3. 候选房源相对近期可比证据是否合理；
4. 存在哪些产权、交易、产品、规划和流动性风险；
5. 哪些事实变化会影响看房、报价或暂缓行动的判断。

系统只提供可解释、可追溯的辅助判断：硬约束与偏好分开，未知值不填零，挂牌不冒充成交，规划不冒充现状，不输出确定涨幅或“稳赚”结论。

## 2. 当前阶段目标

当前不直接建设全杭州完整决策产品，而是先完成**西湖区住宅小区数据底座和一个真实小区的端到端证据链**：

`来源登记 → 原始快照 → 小区主数据 → 实体匹配 → 学区/交通/市场事实 → 指标 → 人工复核 → API/页面展示`

首个试点为**耀江文鼎苑**。地址、坐标、市场板块和首期竣工年份已经独立来源核验；历史成交与当前在售的最小闭环已经完成。学区、交通和生活配套仍须进入正式阶段 2 后核验。

## 4. 分阶段验收标准

### 阶段 0：工程与治理底座

交付：可重复本地环境、迁移、来源登记、许可字段、质量报告和最小 API/页面。

验收标准：

- `./dev.sh check` 通过；`start → status → restart → stop` 可重复执行且不遗留监听进程；
- API 与 Web 均通过 URL 就绪检查，启动失败会返回非零状态、打印日志并回收进程；
- SQLite 可从空库迁移至最新版本；同一迁移在 MySQL 8.x 实际执行成功；
- 每个外部来源具有许可、使用限制、观察时间和来源 URL 字段；
- 测试覆盖幂等导入、来源追踪、迁移和 API 健康检查。

**当前状态：代码级完成；17 项测试通过，21 个受限旧市场板块已失效。尚缺真实 MySQL 8 实机迁移验收。**

### 阶段 1：西湖区小区主数据

交付：由至少两个独立、允许再利用的来源合并形成主清单，并有可操作的人工复核队列。

验收标准：

- 两个来源均完成许可核对，且原始记录可追溯；
- 以两来源合并去重结果定义覆盖率分母，主清单覆盖率 ≥95%；
- 标准地址与坐标完整率 ≥98%，基础属性 P0 完整率 ≥85%；
- 自动匹配保留分项依据与置信度，高/中/低阈值有固定测试样例；
- 人工抽检至少 50 个候选，实体合并准确率 ≥98%；
- 候选、已核验、误标和已停用状态不能混用。

**当前状态：试点完成、全区未达标。耀江文鼎苑已核验且地址/坐标完整；西湖区全量主清单、双来源覆盖率和 50 个样本抽检尚未完成。**

### 阶段 2：教育、交通与生活配套

交付：年度学区、运营交通和基础 POI 的版本化事实及证据。

验收标准：

- 当年学区映射覆盖率 ≥90%，其余明确为待核验；
- 每条学区映射具有学年、官方来源、原文和人工确认状态；
- 运营、在建和规划交通分层保存，只有运营线路计入当前通勤；
- 医疗、商业、公园等 POI 保存来源、坐标系和更新时间；
- API 能展示原始证据、数据日期和缺失状态。

**当前状态：未开始。**

### 阶段 3：市场观察与指标

交付：挂牌、调价、网签/成交的分口径事实，月度聚合、流动性和置信度指标。

验收标准：

- 市场数据来源明确允许项目所需的获取、缓存和内部使用；
- 挂牌、调价、网签/成交具有独立类型与定义，绝不混算；
- 指标保留样本数、时间窗、分位数、输入版本和规则版本；
- 外部市场事实来源可追溯率 100%，口径标注率 100%；
- 固定样例可从原始记录重算出一致指标，样本不足时自动降级或隐藏。

**当前状态：试点最小闭环完成。正式库已有 10 条历史成交和 10 条当前挂牌观察，其中 4 条来自 TMSF 小区详情公开页；月度聚合、价格曲线和流动性指标尚未实现。**

### 阶段 4：个人决策闭环

交付：家庭画像、预算、硬约束、候选比较、风险清单、看房记录与报价依据。

验收标准：

- 使用真实家庭场景完成从初筛到报价依据的端到端验收。

## 5. 数据流程与开源项目方法调研结论

已完成第一轮 Git 仓库方法调研，详见[数据流程与开源项目方法调研](数据源与开源项目调研_2026-09-29.md)；市场站点与接入边界详见[市场数据源调研与接入结论](市场数据源调研_2026-09-29.md)。调研目标是提炼适合本项目的核心逻辑和流程，不是直接复用仓库数据或站点爬虫。

核心判断：

- 借鉴 OSMnx/osmdata 的 polygon 分片、空间裁剪、请求缓存和服务端状态感知，重构 OSM 候选发现流程；
- 借鉴通用房产采集项目的分区任务、有限重试、抖动、限速、运行指标和失败重放，但将采集、解析、规范化和发布彻底分层；
- 借鉴杭州房产项目的“行政区 → 小区 → 房源”对象层级和分页不完整性处理，不复制与具体网站绑定的抓取实现；
- 第二来源接入后，用人工标注集比较当前确定性规则与 dedupe；达到数万条、多字段数据后再评估 Splink；
- 最终统一为来源适配器 + 通用执行器，让 OSM、政府文件、人工审核快照和未来授权数据共享同一套状态机、证据链和质量报告；CSV 只作为测试夹具或人工快照回退入口，不是用户前置条件。

## 6. 下一迭代优先级

### P0：单小区市场闭环

先围绕一个小区解决两个最有价值的问题，不等待全区主数据、学区和生活圈全部完成：

1. **历史销售记录**：支持按小区查看可追溯的成交/网签观察记录，字段至少包括事件日期、总价、单价、面积、户型、楼层、来源、口径和置信度；后续按月聚合中位价、样本量和 P25/P75 区间，绘制价格波动曲线。
2. **当前在售房源**：支持查看当前挂牌快照，字段至少包括来源房源 ID、挂牌时间、总价、单价、面积、户型、楼层、朝向、装修、来源链接和最近观察时间；同一来源房源重复导入必须更新快照而不是生成重复记录。

数据源优先级：链家 → 我爱我家 → 透明售房网。前一来源无法稳定取得或字段不足时，才启用下一来源；不同来源记录保留独立来源标识，不直接混合去重。

P0 的最小验收标准：

- `observation_type` 明确区分 `deal`/`transaction`、`listing` 和其他观察类型，挂牌不得混入成交曲线；
- 同一来源的 `external_id` 幂等，重复导入不增加重复观察；
- 小区详情 API 同时返回历史记录、当前在售记录和数据日期/来源；
- 历史数据按事件日期升序展示，记录不足时明确显示“暂无样本”，不显示虚构趋势；
- 在售列表显示最近观察时间和来源链接，无法判断仍在售的记录标记为过期或未知；
- 使用一份人工审核快照（可由来源适配器生成，CSV 仅作为测试夹具）完成“导入 → API → 页面”的端到端测试；自动来源必须先完成条款、robots 或授权核对。

12. 将链家作为单小区市场数据第一候选源，先验证公开页面的访问稳定性、字段完整性、robots/条款和低频采集可行性；在此之前不宣称“全量”或“官方完整成交”。
13. 将链家解析结果接入 `market_observation`，完成耀江文鼎苑“来源 → 快照 → API → 页面”的首个真实闭环。
14. 在链家闭环验收后，按优先级接入我爱我家和透明售房网，作为补充来源和交叉核验。
15. 完成耀江文鼎苑的基础身份和市场证据链后，再进入学校、地铁、医院和商业 POI 数据域。

## 7. 不变边界

- 不绕过 WAF、验证码、登录限制或网站明确设置的访问控制；
- 不因开源爬虫存在就推定目标网站数据允许复制或再发布；
- OSM 对外展示必须署名并遵守 ODbL，发布衍生数据库前复核 share-alike 义务；
- 候选对象不等于真实小区，未经人工或第二来源验证不得标记为 `verified`；
- 未知值保持未知，来源或许可不清的数据不得进入可发布指标。
