# 市场数据源调研与接入结论（2026-09-29）

## 结论先行

当前没有发现一个同时满足“可公开稳定访问、包含完整成交价、提供实时在售房源、且明确允许自动抓取与缓存”的单一来源。因此，项目不应把某个网站页面直接当成权威数据库，也不需要用户先准备本地 CSV。

本项目采用“来源适配器 → 原始快照 → 规范化观察记录 → 人工复核 → 页面展示”的分层流程。来源优先级固定为：**链家 → 我爱我家 → 透明售房网**；58 和房天下作为补充参考与交叉核验。现阶段可确认的数据能力如下：

| 目标 | 可确认来源 | 能提供什么 | 当前限制 | 接入结论 |
|---|---|---|---|---|
| 价格趋势参考 | [58 同城耀江文鼎苑小区页](https://hz.58.com/xinfang/xq100467786-fangjia.html) | 页面公开展示近 36 个月月度参考均价、地址和小区基础信息 | 是聚合参考价，不是逐笔网签成交；自动化使用条款仍需确认 | 可作为“参考价格曲线”适配器的第一候选，必须标注口径和来源日期 |
| 历史成交样本 | [房天下杭州历史成交页](https://m.fang.com/chengjiao/hz/?projcode=2010064400) | 可看到耀江文鼎苑的成交日期、面积、户型、朝向、楼层等记录 | 价格存在遮挡（如 `2**万`），不能还原精确总价；不能宣称为完整官方成交库 | 可作为人工核验的成交事件样本；遮挡价格保持未知 |
| 当前在售快照 | [链家杭州站](https://hz.lianjia.com/)、[耀江文鼎苑 TMSF 小区页](https://www.tmsf.com/esf/xq_index_10003660.htm)、[我爱我家小区挂牌页](https://hz.5i5j.com/ershoufang/100000000005213/r5/) | TMSF 小区页实测展示挂牌总数 175 套、近 30 日签约 8 套和 4 张直接展示的出售卡片；卡片含房源 ID、总价、单价、面积、户型和“产权核验”标记 | 175 是页面聚合计数，本轮只能取得页面直接展示的 4 张卡片；非浏览器 HTTP 请求触发 WAF | 已接入正常浏览器完整 HTML/审核 JSON 快照导入；不把 4 张卡片宣称为 175 套全量数据 |
| 权威交易核验 | 杭州市住保房管部门的个人房屋合同/登记查询 | 说明官方系统存在合同和登记查询能力 | 查询通常需要本人身份或授权，不是公开按小区批量查询接口 | 作为争议记录的授权核验渠道，不作为当前自动数据源 |

## 为什么现在不能直接“自动抓一份数据”

公开页面能证明“页面上存在可读字段”，不等于项目获得了批量复制、长期缓存或再发布授权。链家公开承诺真实在售、真实价格和真实房源，但其页面仍提示房源信息应以产权证明或政府类网站核验；透明售房网页面明确标注其数据来自杭州二手房交易监管平台，房天下页面还会遮挡价格。因此，链家可以作为第一候选源，但仍不能直接填充为“官方完整成交数据库”。

因此，数据模型中的 `source_url`、`observed_at`、`confidence`、`observation_type` 和原始快照必须保留。无法确认的价格写入空值并标记原因，不能用估算值补齐；挂牌和成交必须分开，不能混画一条曲线。

## 分阶段接入方案

### 阶段 A：前端验收所需的最小真实闭环

1. 以链家小区挂牌页和房源详情页作为当前在售的第一候选来源，记录公开字段、链家房源编号、来源 URL 和最近观察时间。
2. 以链家小区成交页（页面可见时）作为历史成交第一候选；成交页面缺失或字段不足时，降级为公开样本并标记低置信度，不补齐未知价格。
3. 以 58 页面公开的月度参考均价生成“参考价格趋势”，展示口径、月份、来源链接和观察日期；它不与链家逐笔成交混算。
4. 以房天下、透明售房网或我爱我家人工交叉核验少量记录，作为质量抽检，不作为未经授权的批量复制源。
4. API 返回 `history` 与 `listings` 两个集合；没有样本时显示“暂无样本”，不能显示虚构趋势。

### 阶段 B：授权后自动化

只有在链家及其他站点的条款、robots、接口授权或用户提供的合法数据权限确认后，才启用对应自动适配器。第一版只访问公开列表/详情页，不登录、不绕过验证码或 WAF、不调用未公开接口；执行器负责限速、重试、快照哈希、幂等、过期标记和失败重放。

当前代码已提供链家公开房源详情页的低频快照解析入口，要求显式传入 `https://hz.lianjia.com/` 下的公开 URL；解析失败或页面被拦截时保留失败，不降级为猜测数据。

2026-09-29 实机验证发现，链家可能返回 HTTP 200，但正文实际为贝壳信息安全中心的自动化访问拦截页。项目现已增加显式拦截识别，不使用代理池、指纹伪装、隐藏自动化特征或验证码破解。可行回退是由用户在正常浏览器中访问公开列表并保存完整 HTML，再通过 `import-lianjia-html` 进入同一套原始快照、解析、幂等写入和页面展示流程。

### 链家页面与 JSON API 实测

2026-09-29 对耀江文鼎苑相关入口做了低频、匿名、无绕过测试：

| 路线 | 实测结果 | 项目决策 |
|---|---|---|
| `hz.lianjia.com/ershoufang/c.../` 桌面列表 | 安全中心拦截或跳转用户登录 | 不做自动登录；仅在公开可访问时直连 |
| `m.lianjia.com/.../ershoufang/` 移动列表 | 302 跳转 `hip.lianjia.com/captcha` | 不破解验证码 |
| `app.api.lianjia.com/house/ershoufang/searchv4` | HTTP 418，`X-Sec-Action: update` | 旧 App API 已受风控，不接入 |
| `m.ke.com/liverpool/api/ershoufang/getList` | HTTP 418，`X-Sec-Action: captcha` | 移动 JSON API 与网页共用风控，不接入 |
| `news.lianjia.com/hz/xiaoqu/...` 资讯页 | HTTP 200，可看到聚合价格和推荐房源 | 仅作低置信度人工参考；无房源 ID/可靠更新时间，且页面“当前在售数”和推荐卡片可能矛盾，不进入当前在售口径 |

因此，JSON API 并不是天然更稳定的合规通道。历史开源项目中出现的 App 接口依赖旧协议、客户端参数甚至签名机制，不能据此推定当前接口允许匿名抓取。当前可落地路径仍为：公开页面低频直连 → 明确拦截识别 → 浏览器人工保存 HTML 导入 → 我爱我家/透明售房网补充；若需要链家全自动和持续更新，应申请正式授权或数据合作接口。

统一更新入口现已实现逐源熔断：链家触发拦截后记录 `blocked` 并打开该来源熔断，但继续处理我爱我家和透明售房网；每个来源均输出独立状态。我爱我家在 2026-09-29 的本机普通 HTTP 请求中也出现重定向循环并最终返回 `403 / Ws-Action: bot`，因此自动更新只能消费已取得并审核的快照，不能假设始终可直接抓取。

TMSF 实测确认：正常浏览器能够搜索耀江文鼎苑并打开 `xq_index_10003660.htm`，页面直接展示 4 张出售卡片；小区搜索 JSON 和详情页的普通 HTTP 请求均会返回阿里云 WAF JavaScript challenge。项目新增 `collect-tmsf-community`、`import-tmsf-html`、`tmsf_public_v1` 解析器和独立熔断状态，挑战出现后不重试绕过。正式库已导入这 4 张页面可见卡片。

杭州二手房交易监管服务平台公开旧域名 `jjhygl.hzfc.gov.cn` 当前 DNS 不可解析。项目保留旧公开 JSON 结构的独立适配器和 `collect-hangzhou-official` 探测命令，但其当前验收结果是 `unavailable`；TMSF 页面虽声明市场信息来自杭州市住保房管网，也不能因此在数据血缘上冒充“官方平台直采”。

### 阶段 C：权威数据增强

如果后续能取得住保房管部门、经纪平台或商业数据服务的授权数据，再将授权的逐笔成交接入 `deal/transaction`，并按月计算中位数、P25/P75 和样本量。未取得授权前，页面名称应使用“市场参考/公开样本”，而不是“官方完整成交”。

## 对当前实现的影响

- 用户不需要准备本地 CSV；CSV 导入命令仅保留为人工审核快照和测试夹具的回退入口。
- `market_observation` 继续作为统一规范化表：`deal/transaction` 表示成交事件，`listing` 表示挂牌快照，月度参考价应使用独立口径或 payload 标记，不能伪装成逐笔成交。
- 页面必须显示数据日期、来源和置信度，并对价格遮挡、记录过期、来源未授权等情况给出明确提示。
